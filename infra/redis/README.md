# Redis users (ADR-009, ADR-005)

`users.acl.tmpl` is rendered by `entrypoint.sh` (passwords from `REDIS_ADMIN_PASSWORD`, `REDIS_API_PASSWORD`, `REDIS_JUDGE_PASSWORD`) and loaded with `--aclfile`. Redis ACL files cannot hold comments, so the reasoning lives here. The same file and script are what the tests start (`apps/worker/internal/worker/acl_test.go`, `apps/api/src/redis/acl.test.ts`), so the tests check what compose and production run.

| User      | Used by                                                | Can                                                                                                                                                                                                                                                                                   | Cannot                                                                                                                                                                                               |
| --------- | ------------------------------------------------------ | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `default` | nobody                                                 | nothing: the user is off, every client must authenticate                                                                                                                                                                                                                              |                                                                                                                                                                                                      |
| `admin`   | operations, backups, tests, the compose healthcheck    | everything                                                                                                                                                                                                                                                                            | is never given to the app or a judge                                                                                                                                                                 |
| `api`     | the API (production `REDIS_URL`)                       | all keys and channels (it owns the keyspace), scripting for the enqueue script                                                                                                                                                                                                        | the `@dangerous` and `@admin` commands: `FLUSHALL`/`FLUSHDB`, `KEYS`, `CONFIG`, `ACL`, `DEBUG`, `SHUTDOWN`, `REPLICAOF`, `MONITOR`, `SAVE`, `SLOWLOG`, ...                                           |
| `judge`   | workers on untrusted hosts (`REDIS_URL` of the worker) | on `jobs:*`: `XREADGROUP`, `XACK`, `XCLAIM`, `XAUTOCLAIM`, `XPENDING`, `XDEL`, `XGROUP CREATE`; `XADD` on `jobs:dlq` and `jobs:quarantine`; `HINCRBY/HGET/HDEL` on `jobs:crashes`; `XADD` on `results`; `PUBLISH` on `progress:*`; `SET` and `EXISTS` on `hb:*`; `MULTI/EXEC/DISCARD` | read any other key or channel, `GET`, `KEYS`, `SCAN`, `FLUSHALL`, `EVAL`, `INFO`, `CONFIG`, `ACL`; add jobs to a lane; read `results`; touch tickets, rate limits, replay streams or the SSE fan-out |

Residual power of a compromised judge, accepted: it can acknowledge or delete jobs it can see (the reconciler, FR-QUEUE-09, re-enqueues them), post wrong results for jobs (schema and run-version checks in the API limit this), and fake heartbeats.

Dev stack: the API's default `REDIS_URL` still uses `admin` for convenience; production sets `REDIS_URL` explicitly (config refuses to start without it) and must use the `api` user. After changing this file run `docker compose up -d --force-recreate redis`.
